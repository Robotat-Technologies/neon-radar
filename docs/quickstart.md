# Quickstart (Phase 1)

One command starts the NeonRadar demo on your machine: a Neo4j graph loaded with the synthetic demo-mini dataset, one detection run, the API and the explorer UI. Every company, person, account and payment in it was generated by NeonRadar; none of them exists. Everything listens on `127.0.0.1` only and nothing is sent anywhere.

## Requirements

| What | Why |
|---|---|
| macOS or Linux (on Windows, WSL 2) with 16 GB of memory; 8 GB works with the small profile below | Neo4j, the API and the UI run side by side |
| Docker Desktop or Docker Engine with Compose v2.20 or later; give Docker's VM at least 6 GB (Docker Desktop, Settings, Resources) | everything runs in containers |
| [uv](https://docs.astral.sh/uv/) 0.13 (it installs Python 3.14) | the `neonradar` command loads the data |
| ICU headers and `pkg-config` (macOS: `brew install icu4c pkg-config` and point `PKG_CONFIG_PATH` at icu4c's `lib/pkgconfig`; Debian or Ubuntu: `sudo apt-get install pkg-config libicu-dev`) | PyICU, which FollowTheMoney needs, builds from source |
| Node.js 24.12 or later | `make setup` installs the UI's packages; `make e2e` runs the browser test |
| Free ports `7474`, `7687`, `8000` and `8080` on `127.0.0.1` | Neo4j Browser, Bolt, the API and the UI |
| Network access on the first run | to pull the Neo4j, uv Python, Node and nginx images, download the pinned Graph Data Science jar (about 64 MB, checked against its SHA-256) and install packages while the images build; later runs need none |

`uv run neonradar doctor` checks Docker, Compose, `.env`, the ports, ICU and the memory Docker has.

## Run it

```bash
git clone https://github.com/robotat-com/neon-radar.git
cd neon-radar
make setup        # Python and npm packages, pre-commit hooks, .env with a generated Neo4j password
make demo-mini
```

`make demo-mini` creates `.env` if it is missing, fetches the pinned GDS jar if it is missing, starts Neo4j and waits until it is healthy, applies the schema migrations, wipes the graph and loads `data/fixtures/demo-mini/`, runs detection, builds and starts the API and the UI, and waits until both are healthy. It ends like this:

```text
NeonRadar demo-mini is running on synthetic data:
  UI             http://localhost:8080
  API docs       http://localhost:8000/docs
  Neo4j Browser  http://localhost:7474
Elapsed: 151 s (2 min 31 s). Stop it with 'make down'.
```

The first run builds two images and takes a few minutes; the target is under five minutes on a 16 GB laptop. Later runs reuse the images unless the code changed.

## What you see

- **The UI** at http://localhost:8080. Every page shows the standing disclaimer and the synthetic demo notice. Search for a name (the first word of a company name, for example), open an entity to see its network one to three hops out, and open **Alerts**.
- **Alerts.** The detection run looks for funds that leave an account and return to it through a chain of transfers (the circular-flow typology, `docs/typologies/circular-flow.md`). The planted scenario appears as an alert whose headline starts with "Synthetic scenario". A benign look-alike, a loan paid out and paid back, may appear too: the typology file lists it as a known false positive. An alert page shows the evidence graph, one explanation step per transfer (select a step to highlight it), the metrics and the typology's sources. A match describes a structure; it is not evidence of wrongdoing.
- **The API** at http://localhost:8000/docs: every endpoint of the read-only API (contract C3, `contracts/C3-api.md`).
- **Neo4j Browser** at http://localhost:7474: connect to `neo4j://localhost:7687` as `neo4j` with the `NEO4J_PASSWORD` from `.env`. Try `MATCH p = (:Account)-[:PAID]->{2,6}(:Account) RETURN p LIMIT 25`.

## The end-to-end test

With the demo running:

```bash
npx --prefix ui playwright install chromium   # once: downloads Playwright's Chromium
make e2e
```

It checks the notices, a search for the first company in the fixture, the alert list, an alert page and an entity page, in headless Chromium. The report is in `ui/playwright-report/`. CI runs the same two commands in `.github/workflows/e2e.yml` on every push to `main` and on pull requests labelled `e2e`.

## Without Docker: `make demo-dev`

In the devcontainer or a Codespace, where Neo4j already runs and there is no Docker, `make demo-dev` loads the same data into the Neo4j at `NEO4J_URI`, runs detection, then starts `neonradar api serve` and the Vite dev server. The UI is at http://localhost:5173 and `make e2e E2E_BASE_URL=http://localhost:5173` tests it. Ctrl-C stops both servers.

## Stop and reset

| Command | What it does |
|---|---|
| `make down` | stops Neo4j, the API and the UI; the graph is kept |
| `make demo-mini` | starts everything again; it always wipes the graph and loads the demo afresh |
| `make reset CONFIRM=yes` | deletes the Neo4j data and logs volumes; the next start is empty |
| `docker image rm neonradar-api neonradar-ui` | frees the disk space of the two demo images |

The demo replaces whatever is in the graph. If the graph holds anything that is not synthetic (for example registry data you loaded yourself), `make demo-mini` stops before changing it and says so. `make demo-mini CONFIRM=yes` deletes that data and loads the demo.

## Troubleshooting

**Memory.** Pick a profile in `.env`; the Neo4j container never uses more than `NEO4J_MEM_LIMIT`.

| Profile | Laptop | `NEO4J_HEAP` | `NEO4J_PAGECACHE` | `NEO4J_MEM_LIMIT` |
|---|---|---|---|---|
| standard (default) | 16 GB | `2G` | `2G` | `5g` |
| small | 8 GB | `1G` | `512M` | `2500m` |

Neo4j restarting with `OutOfMemoryError`, an image build that stops with `Killed` or exit code 137, or a laptop that slows to a crawl all mean Docker has too little memory: switch to the small profile (`make down`, edit `.env`, `make demo-mini`), close other containers, or give Docker's VM more memory. More in [architecture/local-stack.md](architecture/local-stack.md).

**Ports.** `port is already allocated` or `address already in use` means another program listens on one of the ports. Find it with `lsof -nP -iTCP:8080 -sTCP:LISTEN` (or `uv run neonradar doctor`) and stop it, or move NeonRadar's side: `NR_UI_PORT=8081 make demo-mini` for the UI (then `make e2e E2E_BASE_URL=http://localhost:8081`), `NR_API_PORT` for the API, and `NEO4J_HTTP_PORT` or `NEO4J_BOLT_PORT` for Neo4j. You can also put these in `.env`; if you move the Bolt port, set `NEO4J_URI` there to match so that the other `neonradar` commands find it. The printed URLs always show the ports in use.

**Other problems.**

| Symptom | What to do |
|---|---|
| `The API or the UI did not become healthy` | `docker compose --profile app logs api ui`. The API is healthy only when Neo4j answers with APOC and GDS present. |
| `container ... neo4j-1 is unhealthy` | `make logs`. A password changed after the database was created shows up as failed health checks: `make reset CONFIRM=yes`, then `make demo-mini`. |
| `REFUSED  the graph holds ... entities that are not synthetic` | see "Stop and reset" above |
| `Set NEO4J_PASSWORD in .env` | run `bash scripts/ensure_env.sh` (in a git worktree, in the main checkout first) |
| `make e2e` says Chromium is missing | `npx --prefix ui playwright install chromium` |
