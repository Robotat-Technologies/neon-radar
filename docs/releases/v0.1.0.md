# NeonRadar v0.1.0

The first tagged pre-release of NeonRadar: the Phase 1 foundation and the first part of Phase 2. It runs one synthetic demo end to end on a laptop, with no cloud account and no outbound calls. It is a reference project to learn from and build on, not a finished investigation tool.

> NeonRadar is an educational, open-source tool that finds structural patterns in synthetic or public data. A pattern match is not evidence of money laundering, corruption or any other wrongdoing. There are legitimate reasons for almost every structure shown here, including holding companies, shared registered agents, professional directors, payment intermediaries and cash businesses. Where public data is used, many people and entities share the same or similar names, and source registers contain errors. Nothing here suggests or implies that any identifiable person or entity has broken the law. NeonRadar is not a certified compliance system and does not make anyone compliant with anything. If you find an error in NeonRadar, tell us and we will correct it; errors in source data can only be corrected by the source, and we will tell you where to report them.

## Data notice

> Synthetic data. Every company, person, address, account and payment in this demonstration was generated by NeonRadar, and none of them exists. Patterns that resemble money laundering were planted on purpose to show how such structures look in a graph, next to ordinary activity that only looks similar. Detection results on synthetic data say nothing about how NeonRadar would perform on real data.

- **The demo holds synthetic data only:** the demo-mini dataset in `data/fixtures/demo-mini/`. Any resemblance of a generated name to a real person or company is accidental.
- **Never use the demo, or any alert it shows, to judge a real person or company.** An alert describes a structure in synthetic data; it says nothing about anyone in the world.
- **No real data ships with this release**, and the demo never loads any. The registry loaders below are tested on synthetic fixtures only; running them on real data needs the approvals listed under "What it does not do yet".

## What it does

- **One-command synthetic demo.** `make demo-mini` starts Neo4j 5.26 Community (with APOC Core and the pinned Graph Data Science 2.13.4 jar), applies the schema migrations, loads the synthetic demo-mini dataset, runs detection, builds and starts the API and the explorer UI, and prints their addresses. Everything listens on `127.0.0.1` only.
- **Explorer UI** (Vue 3): entity search, an entity's network one to three hops out, the alert queue and an alert page with its evidence graph, one explanation step per transfer, the metrics and the typology's sources. Every page shows the standing disclaimer and the synthetic demo notice.
- **Read-only API** (FastAPI, `/api/v1`): health, meta, search, entities and their networks, alerts and typologies, with interactive documentation at `/docs` (contract C3, `contracts/C3-api.md`).
- **One detector: circular flows.** It looks for funds that leave an account, pass through other accounts and return to the originator, a pattern described in the typology's sources [fatf_egmont_tbml_indicators_2021] [ffiec_appendix_f]. The definition is `detect/typologies/circular_flow.yaml` (status draft). Each alert carries its evidence subgraph, its metrics and an explanation; alerts on synthetic scenarios start with "Synthetic scenario".
- **Typology catalog.** Fifteen typology definitions in `detect/typologies/`, all `draft`, each with its cited sources and a plain-language explainer in `docs/typologies/` (also `draft`); `docs/typologies/README.md` lists them.
- **Frozen contracts** at the tag `contracts-v1.2.0`: C1 record format 1.1.0 (FollowTheMoney-based, `contracts/C1-record.md`), C2 graph schema 1.2.0, C3 API 1.1.0 and C4 alert format 1.0.0, with JSON Schemas and the OpenAPI snapshot generated from the models.
- **Registry loaders (synthetic-tested).** Companies House (companies, persons with significant control, officers), GLEIF (LEI records and Level 2 accounting consolidation, loaded as consolidation and never as ownership) and the ICIJ Offshore Leaks Database build C1 records for a profile (`neonradar ingest build`).
- **Data manager.** `neonradar data profiles`, `fetch`, `status` and `purge`: which profiles may run on this machine, downloads with versions and ages, retention, and purging by scope. Real-data commands print counts only.
- **Matching keys.** The `neonradar_keys` package: the pure functions that entity resolution will use to compare names, identifiers and addresses, including names written in Arabic, Cyrillic and Latin scripts.
- **Tooling.** `neonradar doctor` checks a machine (Docker, Compose, ports, ICU, memory); the synthetic generator (`neonradar synth demo-mini`); graph commands (`neonradar graph migrate`, `load`, `wipe`, `smoke`); a Playwright end-to-end test of the demo (`make e2e`).
- **Documentation that teaches the subject:** the wording rules, a glossary, learning cases, the onboarding assignments and the architecture notes under `docs/`.

## What it does not do yet

- **Real-data loading needs keys and approvals.** It stays off until the operator files the data protection documents, lists an approved machine in `docs/data/real-data-machines.md` and enables a profile in `docs/build/project.yaml` (`access.real_data_profiles`, empty in this release); Companies House also needs an API key in `.env`. See `docs/data/real-data-handling.md`.
- **Phases 2 to 4 are in progress.** Not in this release: entity resolution and its benchmark, loading registry data into the graph, the official sanctions list loaders (Phase 2); detectors for the other thirteen typologies (the fifteenth, `trade_based_ml`, is an explainer only), the synthetic world generator and the evaluation harness (Phase 3); the investigation copilot (Phase 4: `POST /api/v1/copilot/ask` answers 501 Not Implemented).
- **Three API routes answer 501 Not Implemented.** `GET /api/v1/entities/{id}/ownership`, `GET /api/v1/paths` and `GET /api/v1/entities/{id}/resolution` are part of the C3 1.1.0 snapshot and appear on the `/docs` page, but they answer 501 Not Implemented until the graph API milestone (M2.12) adds them.
- **No typology is approved.** Every definition is `draft` until a typology researcher approves it.
- **Not a compliance system,** not real-time, not a hosted service, and no machine learning.

## Run the demo

### System requirements

| What | Why |
|---|---|
| macOS or Linux (on Windows, WSL 2) with 16 GB of memory. The small memory profile in `docs/quickstart.md` is meant for 8 GB, but this release has not verified it (see Known issues) | Neo4j, the API and the UI run side by side |
| Docker Desktop or Docker Engine with Compose v2.20 or later; Docker's VM given at least 6 GB | everything runs in containers |
| [uv](https://docs.astral.sh/uv/) 0.13 (it installs Python 3.14) | the `neonradar` command loads the data |
| ICU headers and `pkg-config` (macOS: `brew install icu4c pkg-config`, with `PKG_CONFIG_PATH` pointing at icu4c's `lib/pkgconfig`; Debian or Ubuntu: `sudo apt-get install pkg-config libicu-dev`) | PyICU, which FollowTheMoney needs, builds from source |
| Node.js 24.12 or later | the UI's packages and the end-to-end test |
| Free ports `7474`, `7687`, `8000` and `8080` on `127.0.0.1` (or move them, below) | Neo4j Browser, Bolt, the API and the UI |
| Network access on the first run only | to pull the Neo4j image and the build images, download the pinned GDS jar (about 64 MB, checked against its SHA-256) and install packages; later runs need none |

### Commands

```bash
git clone https://github.com/robotat-com/neon-radar.git
cd neon-radar
git checkout v0.1.0
uv run neonradar doctor   # optional: checks Docker, Compose, ports, ICU and memory
make setup                # Python and npm packages, pre-commit hooks, .env with a generated Neo4j password
make demo-mini            # Neo4j, migrations, demo-mini, detection, API and UI; prints the URLs
```

Then open:

- the UI at http://localhost:8080 (search for the first word of a company name, open an entity, open **Alerts**);
- the API documentation at http://localhost:8000/docs;
- Neo4j Browser at http://localhost:7474 (user `neo4j`, the `NEO4J_PASSWORD` from `.env`).

The first run builds two images and takes a few minutes. With the demo running, `npx --prefix ui playwright install chromium` (once) and `make e2e` run the browser test.

If a port is taken, move NeonRadar's side, for example `NR_UI_PORT=8081 make demo-mini` (also `NR_API_PORT`, `NEO4J_HTTP_PORT`, `NEO4J_BOLT_PORT`); the printed URLs show the ports in use.

Stop and clean up:

```bash
make down                  # stops Neo4j, the API and the UI; the graph is kept
make reset CONFIRM=yes     # deletes the demo's Neo4j data and logs volumes
docker image rm neonradar-api neonradar-ui   # frees the two demo images
```

Troubleshooting is in `docs/quickstart.md`.

## Known issues

- **Neo4j can run out of memory inside its container.** Both memory profiles in `docs/quickstart.md` leave about 1 GB for Neo4j above `NEO4J_HEAP` plus `NEO4J_PAGECACHE` (standard: 2G and 2G in `5g`; small: 1G and 512M in `2500m`). In the release check (a busy, shared Docker VM with 16 CPUs and 7.75 GiB), the Neo4j container with the small profile was killed for memory (exit code 137) and restarted by Compose; at rest it used 2.0 of its 2.44 GiB. Earlier runs with 1 GB or less of that headroom stopped with `Neo4j not reachable` during `graph load` or `detect run`. If that happens, close other containers, give Docker's VM more memory and raise `NEO4J_MEM_LIMIT` so that it leaves more room, for example `NEO4J_HEAP=1G NEO4J_PAGECACHE=512M NEO4J_MEM_LIMIT=3500m make demo-mini`.
- **Neo4j can take longer to start than its health check allows.** The health check in `compose.yaml` gives Neo4j about three minutes (a 30-second start period, then 30 checks 5 seconds apart). In the release check, on a loaded machine, Neo4j took four minutes to accept connections and `make demo-mini` stopped with `container ... neo4j-1 is unhealthy`. If that happens, wait until Neo4j is up (`make logs`) or close other containers, then run `make demo-mini` again. `make reset CONFIRM=yes`, which the quickstart's troubleshooting table suggests for a changed password, does not help here and deletes the demo's data.
- `docs/build/PROGRESS.md` still shows some merged Phase 1 and Phase 2 milestones as `pr-open`.
